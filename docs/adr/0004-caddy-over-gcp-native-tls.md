# Use Caddy for TLS instead of GCP-native options

GCP's Google-managed SSL certificates are only available behind a GCP HTTPS Load Balancer or via Cloud Run domain mapping — not on a bare Compute Engine VM. We considered both: an HTTPS Load Balancer costs a minimum of $18.25/mo for the forwarding rule alone (before any data processing charges), and Cloud Run's free tier only covers request-driven traffic, not a resident always-on process, so keeping `min-instances=1` for continuous background polling isn't free either. Both would meaningfully undercut the reason this whole host is a GCP `e2-micro` Always Free VM in the first place. We chose Caddy running on the VM itself instead, self-managing free Let's Encrypt certificates — GCP's own documentation lists this as the standard alternative for exactly this case (a standalone VM without a load balancer). The trade-off is operational: Caddy (and its cert renewal) is now something we run and maintain ourselves rather than something GCP manages for us.
