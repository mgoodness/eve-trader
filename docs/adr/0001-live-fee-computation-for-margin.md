# Compute Margin fees from live character skills/standings, not a fixed config value

The scanner's Margin figure needs Fees subtracted to be accurate, and Fees depend on the character's Accounting and Broker Relations skill levels plus corp/faction standings — all of which vary per character and change slowly over time. We considered asking the user to configure a fixed fee percentage once (simpler, no extra ESI scopes) but chose instead to compute Fees from the character's actual skills (`esi-skills.read_skills.v1`) and standings (`esi-characters.read_standings.v1`) via ESI, cached for 24 hours. This costs two additional OAuth scopes beyond the market-order scopes already needed, but keeps Margin accurate automatically as the character trains skills or standings shift, rather than silently drifting from a stale manually-entered number.
