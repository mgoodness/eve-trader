# Compute Realized Margin fees from the existing live formula, not the wallet journal

Realized Margin needs Fees subtracted, same as Margin. ESI's wallet-transactions endpoint (the source for Wallet Transactions, per CONTEXT.md) carries no fee data — the actual broker-fee and sales-tax amounts charged on a trade live only in a separate wallet *journal* endpoint, correlated back via `journal_ref_id`, and would require its own ESI integration (though no new OAuth scope: `esi-wallet.read_character_wallet.v1` already covers both). We considered pulling those actual recorded amounts, which would be exact down to the ISK even for retroactive skill/standing changes, but chose instead to apply the same live Fee formula already used for Margin (ADR-0001/0006) to each Matched Trade's real fill prices. This keeps Realized Margin numerically consistent with Margin elsewhere in the app and avoids a second data-fetching path for #70's initial scope, at the cost of Realized Margin being a formula-derived approximation rather than the wallet's actual recorded fee charge — a gap worth knowing about if a future ticket asks why a Matched Trade's Realized Margin doesn't reconcile exactly to the character's wallet balance change.
