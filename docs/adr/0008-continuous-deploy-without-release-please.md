# Continuous deploy on merge, instead of release-please-gated releases

release-please's model — batch Conventional Commits into an accumulating version-bump PR, and only cut a release (tag, GitHub Release, Docker image) once a human merges that PR — exists to solve a problem this app doesn't have: curating what goes into each release for a userbase that needs stable, numbered versions to track. eve-trader has exactly one user (see the README's Status section) who's fine with every merge to `main` shipping as soon as it lands. In practice release-please was just an extra PR to review and merge before a fix or feature actually deployed, with no one relying on its version numbers or changelog.

We backed it out: `release-please.yml`, `release-please-config.json`, and `.release-please-manifest.json` are gone, and the former tag-triggered `release.yml` is now `deploy.yml`, triggered directly on push to `main`. It still uses GoReleaser — the cross-compile-then-stage-into-Dockerfile mechanics in `.goreleaser.yaml`/`Dockerfile` are unrelated to release-please and still pull their weight — but invokes `release --skip=validate,announce` instead of a plain `release` (`--skip=validate` drops the "HEAD must be exactly tagged" check GoReleaser normally enforces, while still publishing), and `release.disable: true` means no GitHub Release or tag gets created at all. The Docker image is tagged `stable` (what Watchtower polls) and the short commit SHA (for pinning/rollback), replacing the old `{{ .Tag }}` semver tag.

`CHANGELOG.md` stops accumulating new entries (nothing generates it anymore) and is left in place as a historical record of the releases that were cut before this change.
